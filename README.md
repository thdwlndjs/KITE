# KITE

만들기 전에 시장의 흐름을 읽고, 가장 위험한 가정을 가장 저렴한 방법부터 검증하는 도구. 배경과 원칙은 `CLAUDE.md`, 현재 진행 중인 검증 사이클의 설계는 `docs/CONTEXT.md`와 `.re0/iteration/`를 참고.

## 지금 있는 것

첫 검증 사이클(0.1-signal-loop)의 신호 수집·집계 도구. "1인 AI 빌더는 만들기 전에 수요를 확인하지 않아 낭비를 겪는다"는 가설을 뒷받침/반박하는 근접 1차 신호(1인칭 경험담)를 웹검색·커뮤니티에서 모으고, 최소 관찰 기준(소스 3곳 이상, 신호 15~20건 이상) 대비 현재 상태를 보여준다.

수집 자체(웹검색·페이지 열람)는 지금은 자동 스크립트가 아니라 Claude Code 에이전트가 직접 수행한다 — 결과를 사람이 검토해 채택한 뒤 아래 도구로 저장·집계한다. 왜 이런 구조인지는 `.re0/iteration/0.1-signal-loop/MEMO.local.md`에 기록되어 있다.

## 실행 방법

```bash
node collector/seed_0_1.js          # 1차 DRIVE에서 채택한 신호 (재실행해도 중복 없이 같은 결과)
node collector/seed_0_1_round2.js   # 2차 DRIVE(이터레이션) — 게이트 통과에 필요한 신호 추가
node collector/report.js            # 게이트(소스 다양성/최소 관찰량/축 커버리지) 대비 현재 상태 출력
```

또는 `npm run report`.

## 데이터

- `data/signals.jsonl` — 채택된 근접 1차 신호(출처·인용·날짜·매칭 축·태그).
- `data/context_only.jsonl` — 기준 미달로 기각했거나 접근 실패한 후보(판단 집계에는 안 들어감, 맥락 참고용).

이 파일들은 저장소에 커밋되는 실제 증거 기록이다 — 삭제하지 말고, 다음 사이클에서 이어서 채운다.
